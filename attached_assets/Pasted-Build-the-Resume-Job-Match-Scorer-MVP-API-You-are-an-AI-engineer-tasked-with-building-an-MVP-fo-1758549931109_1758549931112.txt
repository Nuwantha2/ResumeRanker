Build the “Resume / Job Match Scorer” MVP API

You are an AI engineer tasked with building an MVP for the Resume / Job Match Scorer API. Deliver a production-ready backend service that accepts resumes and job descriptions, returns a match score (0–100), lists missing keywords, and provides ATS-friendly formatting hints. The service must be containerized, documented, test-covered, and ready to publish on RapidAPI.

High-level goals (MVP)

Accurate relevance scoring using embeddings + heuristic boosts.

Robust parsing of uploaded resume files (PDF / DOCX) to extract plain text.

Clear JSON API, OpenAPI spec, example SDK snippets (Python + JavaScript).

Lightweight infra: no GPU required. CPU inference allowed.

Safety & privacy: do not store files/text beyond request lifetime unless explicitly requested by a paid plan. Encrypt stored data.

Ready-to-list on RapidAPI: show listing copy + 3 pricing tiers suggested.

Functional requirements (endpoints)
1) POST /v1/parse-resume

Accepts:

file (multipart/form-data) — PDF or DOCX or

text (JSON) — raw resume text

Returns: 200 OK

{
  "status": "ok",
  "parsed_text": "Full resume plain text",
  "sections": {
    "contact": "…",
    "summary": "…",
    "experience": ["…", "…"],
    "education": ["…"],
    "skills": ["Python","Kubernetes"]
  }
}


Must gracefully fallback to best-effort parsing when structure is missing.

2) POST /v1/score-match

Accepts JSON:

{
  "resume_text": "…",           // required if file not provided
  "job_description": "…",       // required
  "top_k_keywords": 20,         // optional, default 20
  "return_rewrites": false      // optional: include suggested rewrites for missing bullets (uses LLM; costlier)
}


Returns:

{
  "score": 82.5,                          // 0-100 normalized
  "semantic_similarity": 0.87,            // cosine similarity (0-1)
  "keyword_coverage": {
    "required": ["SQL","Kubernetes"],
    "missing": ["Terraform","Docker"]
  },
  "matched_sections": {
    "experience": 0.72,
    "skills": 0.9,
    "education": 0.2
  },
  "ats_hints": ["Use plain text skills list", "Avoid header footers", "Limit bullets to 2 lines"],
  "explainability": "Top contributing phrases from resume matched with job requirements ..."
}


Score calculation must combine embedding similarity + keyword match ratio + section-weighted boosts (see scoring algorithm below).

3) POST /v1/batch-score

Accepts array of resume_text or files + single job_description (for companies to score many candidates).

Returns array of results with the same schema as score-match.

Must support pagination and basic rate-limiting.

4) GET /v1/health and GET /v1/metrics

Health checks and basic metrics (requests, latency, error rate).

Scoring algorithm (explicit, so AI implements reproducibly)

Preprocessing

Lowercase, normalize punctuation, remove emails/phones from matching (but keep structure).

Extract skills via regex + simple NER (common resume patterns) and from a curated skill list (optional).

Embeddings

Use sentence-transformers (e.g., all-MiniLM-L6-v2) or OpenAI embeddings if the deployment uses a paid provider.

Create an embedding for:

Full job_description (JD)

Resume text

Optional: section embeddings (experience, skills)

Compute cosine similarity → semantic_similarity (0–1).

Keyword coverage

Extract top N keywords from JD using TF-IDF / RAKE or use POS heuristics.

Check presence in resume (exact match + fuzzy match via stemming). Compute keyword_coverage_ratio = matched / required_count.

Section weighting

Weigh sections: experience 0.5, skills 0.3, education 0.1, summary 0.1 (configurable).

Compute section_score = sum(section_similarity * weight).

Final score

final = 0.6 * semantic_similarity + 0.3 * keyword_coverage_ratio + 0.1 * section_score

Normalize to 0–100 and round to 1 decimal place.

Explainability

Return top 3 phrases from resume that contributed the most to similarity (use token-level similarity or simple n-gram overlap scoring).

Non-functional requirements

Latency: median < 600ms for single score-match with CPU embeddings; batch allowed longer.

Throughput: MVP should handle 50 reqs/min on a single small cloud instance.

Availability: 99% for MVP; document known limitations for the free tier.

Security: HTTPS only; sanitize file uploads; run AV scanning on files; basic rate-limiting (per API key).

Privacy: By default, do not persist user data. If storing for analytics, explicitly opt-in with encryption at rest.

Authentication: API Key header Authorization: ApiKey <key>. Simple key management dashboard.

Tech stack & infra (explicit)

Language: Python 3.11

Framework: FastAPI (ASGI)

Embeddings: sentence-transformers (all-MiniLM-L6-v2) local CPU inference OR OpenAI embeddings (configurable via env var)

Doc parsing: python-docx, pdfminer.six or pdfplumber, textract fallback

NER / parsing helpers: spaCy with lightweight models, regex heuristics

Containerization: Docker + Docker Compose for local dev

Queue / background tasks: Celery + Redis (for batch jobs)

DB: PostgreSQL (for API keys, logs) — but keep resume text ephemeral

Storage: S3-compatible for optional stored files (encrypted)

Rate limiting & auth: fastapi-limiter + Redis

CI/CD: GitHub Actions to build, lint (ruff/flake8), run tests, build Docker image, push to container registry

Monitoring: Prometheus metrics endpoint + Grafana dashboard (MVP can expose /metrics)

Deployment: DigitalOcean App Platform or AWS Fargate/ECS (choose single cloud for MVP). Use scalable container. Use automated deploy from main branch.

Tests & acceptance criteria (must be automated)

Parsing tests

Upload several sample PDFs / DOCX with different layouts → assert parsed_text length > 200 and sections.skills contains expected tokens.

Scoring tests

Pre-generated JD and resume pairs with expected score ranges:

Perfect match pair → score > 90.

Tangential match → score 40–70.

Unrelated → score < 30.

Assert keyword_coverage correctly identifies missing keywords.

Batch endpoint

Submit 10 resumes with one JD → response returns 10 results and overall latency < 10s for local test.

Security

Ensure uploading a non-PDF/DOCX returns 400.

Ensure missing auth returns 401.

CI must run tests, linting, and build Docker image.

Sample unit test cases (sketch)

test_keyword_extraction_exact_and_fuzzy

test_embedding_similarity_monotonicity (if you add words to resume matching JD, score increases)

test_parse_pdf_sample (assert sections detected)
